LGG — configuração do ambiente local

Este guia registra o processo realizado e mostra como reproduzi-lo manualmente em uma máquina Windows com Docker Desktop e .NET 8.

O que ocorreu neste ambiente: o container PostgreSQL lgg-postgres já existia, estava em execução na porta 5432 e foi preservado. Não foi criada uma nova imagem PostgreSQL. O schema e as tabelas LGG foram criados nessa instância vazia. O RabbitMQ não existia e foi baixado/criado a partir da imagem rabbitmq:4-management-alpine.

1. Pré-requisitos

  • Docker Desktop iniciado;
  • .NET SDK 8 instalado;
  • repositório LGG clonado localmente.
docker --version
docker compose version
dotnet --info
dotnet build LGG.sln --no-restore

O build da solução foi executado com êxito. Existem avisos de nulabilidade no código, mas nenhum erro de compilação.

2. PostgreSQL — procedimento manual do zero

Estas são as configurações usadas pela LGG: imagem postgres:16, container lgg-postgres, porta do host 5432, porta do container 5432, banco postgres, usuário postgres, senha local admin1234, volume pgdata e schema da aplicação dbggclt.

Se você ainda não possuir um container PostgreSQL, crie uma rede e um volume persistente, baixe/crie a imagem e então inicie o banco com exatamente essas configurações:

docker network create lgg-network
docker volume create pgdata
docker run -d --name lgg-postgres --network lgg-network `
  -p 5432:5432 `
  -e POSTGRES_USER=postgres `
  -e POSTGRES_PASSWORD=admin1234 `
  -e POSTGRES_DB=postgres `
  -v pgdata:/var/lib/postgresql/data `
  postgres:16

Confirme que ele iniciou:

docker ps
docker logs lgg-postgres

O resultado de docker ps deve expor 0.0.0.0:5432->5432/tcp. Isso torna o banco acessível para a API em localhost:5432.

A aplicação usa, por padrão, a conexão abaixo. Se você escolher outro usuário, senha, banco ou porta, sobrescreva ConnectionStrings__Postgres nas configurações da aplicação.

Host=localhost;Port=5432;Database=postgres;Search Path=dbggclt;Username=postgres;Password=admin1234

3. Criar o schema e as tabelas

Os scripts de tabela já existiam em Documentos/Sql. A aplicação espera o schema dbggclt e as tabelas campeonato_mensal, usuario, video, video_ciclo, video_balde, video_estatistica, video_top_dez e email_balde.

A forma recomendada é executar o script adicionado ao projeto. Ele verifica se o schema já existe e, nesse caso, interrompe sem alterar a base:

.\Documentos\Inicializacao\Initialize-LggDatabase.ps1

Para fazer tudo manualmente, no PowerShell, a partir da raiz do repositório:

$sql = "CREATE SCHEMA dbggclt;`n" + @(
  Get-Content -Raw Documentos/Sql/campeonato_mensal.sql
  Get-Content -Raw Documentos/Sql/usuario.sql
  Get-Content -Raw Documentos/Sql/video.sql
  Get-Content -Raw Documentos/Sql/video_ciclo.sql
  Get-Content -Raw Documentos/Sql/video_balde.sql
  Get-Content -Raw Documentos/Sql/video_estatistica.sql
  Get-Content -Raw Documentos/Sql/video_top_dez.sql
  Get-Content -Raw Documentos/Sql/email_balde.sql
) -join "`n"
$sql | docker exec -i lgg-postgres psql -v ON_ERROR_STOP=1 -U postgres -d postgres

Valide o resultado:

docker exec lgg-postgres psql -U postgres -d postgres -c "SELECT table_name FROM information_schema.tables WHERE table_schema = 'dbggclt' ORDER BY table_name;"
Atenção: execute a criação de tabelas somente em uma base vazia ou depois de confirmar que elas ainda não existem. Os scripts originais usam CREATE TABLE, não CREATE TABLE IF NOT EXISTS.

4. RabbitMQ — procedimento manual

O RabbitMQ é usado pela API para publicar mensagens. Para criá-lo sem Compose:

docker run -d --name lgg-rabbitmq --network lgg-network `
  -p 5672:5672 -p 15672:15672 `
  rabbitmq:4-management-alpine

Confira o status e abra o painel:

docker ps
docker logs lgg-rabbitmq

O broker fica em localhost:5672. O painel fica em http://localhost:15672; para acesso local, as credenciais padrão são guest/guest.

5. Alternativa automatizada com Docker Compose

Foi adicionado o arquivo docker-compose.yml. Por padrão ele inicia apenas o RabbitMQ, evitando conflito com o PostgreSQL lgg-postgres já existente:

docker compose -f Documentos/Inicializacao/docker-compose.yml up -d
docker compose -f Documentos/Inicializacao/docker-compose.yml ps

Em outra máquina, sem PostgreSQL, suba também o perfil de banco. Ele monta os scripts SQL e os executa somente na primeira criação do volume:

docker compose -f Documentos/Inicializacao/docker-compose.yml --profile database up -d

As portas e variáveis do Compose podem ser personalizadas criando Documentos/Inicializacao/.env a partir de Documentos/Inicializacao/.env.example.

6. Executar e testar a API

O perfil da API foi ajustado para usar RabbitMqSettings__HostName=localhost. Assim, tanto o F5 da IDE como os comandos abaixo usam o RabbitMQ local:

dotnet run --project src/LGG.Api --launch-profile http

# Em outro terminal
Invoke-WebRequest http://localhost:5212/Teste/teste_publico -UseBasicParsing

Resposta esperada: Api funcionando. A documentação Swagger está em http://localhost:5212/swagger (ou https://localhost:7182/swagger com o perfil HTTPS).

7. Executar os workers

Cada worker roda em seu próprio terminal e faz polling a cada 15 segundos:

dotnet run --project src/LGG.Email.Worker
dotnet run --project src/LGG.VideoCiclo.Worker
dotnet run --project src/LGG.VideoMetricas.Worker
  • Email: busca itens de email_balde e realiza o envio.
  • VideoCiclo: controla ciclos, preenche o balde de vídeos, finaliza métricas e gera o top 10.
  • VideoMetricas: consulta a API do YouTube e persiste as métricas dos vídeos.

8. Arquivos de documentação e configuração criados

  • Documentos/Inicializacao/README.local.md: guia rápido para subir, testar e parar o ambiente;
  • Documentos/Inicializacao/docker-compose.yml: RabbitMQ padrão e PostgreSQL opcional pelo perfil database;
  • Documentos/Inicializacao/.env.example: valores configuráveis do Compose;
  • Documentos/Inicializacao/docker/postgres/init/00-schema.sql: criação do schema para o perfil PostgreSQL do Compose;
  • Documentos/Inicializacao/Initialize-LggDatabase.ps1: inicialização segura do banco PostgreSQL existente;
  • src/LGG.Api/Properties/launchSettings.json: RabbitMQ local configurado nos perfis da API.

9. Encerramento

# Para parar somente os serviços criados pelo Compose
docker compose -f Documentos/Inicializacao/docker-compose.yml down

# Para parar containers criados manualmente
docker stop lgg-rabbitmq
docker stop lgg-postgres
Não use docker compose down -v nem docker volume rm pgdata se quiser preservar os dados locais do PostgreSQL.
